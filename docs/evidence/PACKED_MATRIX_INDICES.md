# Packed matrix indices, not a zero sentinel

The real Map1 preparation (run 36161951276) passed 180 Unity tests and then rejected a mesh at vertex 12 for marker 9. Read-only corpus inspection identified both mob_boar_01.3dc and mob_boar_02.3dc: 41,484 bytes each; version 0, 30 matrices, 845 vertices, 958 triangles, exact EOF. Vertex 12 packs [14,4,5,9] after its sole explicit weight 0.083333328. The last two packed index bytes carry no weights in the 40-byte layout and are not magic markers. They are now preserved, not overwritten. The two-weight path remains w and 1-w; it does not invent extra influences.

EP6 version444 has three explicit weights and four packed indices. Its fourth weight is the complement, not discarded by normalizing the first three. The shared runtime/baked builder now includes and validates this fourth influence. Example china_8yx_mob_long.3DC: 255,768 bytes, SHA256 34998281a2c495e534a8b0f87ee80d24c681188fcde8dc2a2a0a89e8026c343d; vertex160 has indices[16,12,11,17], explicit weights [0.191067502,0.215158671,0.032273762], complementary weight 0.561500065.

The canonical game.exe contains shader text at file offset0x4606ef with blendweight/blendindices declarations and a fourth weighted transform using the complement of x+y+z. Static presence is an anchor, not proof all resources follow the same executed draw path. The formats align with Microsoft's documented D3D9 indexed blending layouts: https://learn.microsoft.com/en-us/windows/win32/direct3d9/using-indexed-vertex-blending and https://learn.microsoft.com/en-us/windows/win32/direct3d9/fixed-function-fvf-codes . No source code from an external implementation was copied.

Validation still rejects nonfinite data, negative weights, excess weights, weighted indices beyond the skeleton, malformed topology and invalid section boundaries. Parser errors retain section offsets. The new all-Map1 MON test collects every model's rig failure before world asset creation, instead of discovering one incompatible model after a twelve-minute import. Passing counts must come from the subsequent Unity run; source analysis does not certify animation parity.
